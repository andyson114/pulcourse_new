# 계산 방법

이 문서는 '지구를 지키는 점심 선택'이 메뉴 이름 하나로 1인분 CO₂e를 구하고, 그 값을 식당 전체의 1년 배출량으로 넓히는 과정을 설명합니다. 모든 설명은 실제 코드에서 옮겼습니다.

- 근거 코드는 [engine.js](../src/readable/engine.js)(계산 엔진), [dash.js](../src/readable/dash.js)(메뉴 비교·시뮬레이터), [app.js](../src/readable/app.js)(교육 모듈), [rolehub.js](../src/build/rolehub.js)(한 달 식단 달력)입니다.
- `src/readable/`의 파일은 압축된 원문(`src/build/app.bundle.js`)을 읽기 쉽게 풀어 놓은 사본입니다. 그래서 함수 이름이 `Q`, `rt`처럼 한두 글자입니다. 이 문서에 나오는 짧은 함수 이름은 지금 빌드를 푼 이 사본의 이름입니다. 코드를 다시 압축하면 이름이 바뀔 수 있습니다.
- 숫자는 공개 데이터([parameters.json](../data/parameters.json), [emission_factors.json](../data/emission_factors.json), [rules.json](../data/dictionary/rules.json))와 앱 코드에 적힌 값만 적었습니다.
- 1인분 분량 데이터는 급식회사 내부 조리지침서(S012)로 만들었고, 공개 데이터(`data/`)에는 넣지 않았습니다. 이 부분은 계산 규칙과 데이터 형식만 설명합니다. 무엇을 공개했고 무엇을 다시 쓸 수 있는지는 [제작 가이드 7-5](BUILD_GUIDE.md#7-5-공개-범위와-라이선스)에 있습니다.
- 내부 자료에서 나온 분량은 싣지 않았습니다. 형식 예시와 3-6절 계산 예의 분량은 가짜 값입니다. 2-6절의 기본값은 코드에 적힌 실제 값입니다.
- 데이터 파일의 항목별 설명은 [데이터 설명서](DATA.md)에 있습니다.

## 한눈에 보기

1. 메뉴 이름을 정리하고 단어로 나눕니다. 단어에서 재료, 조리법, 수식어를 찾습니다.
2. 재료마다 1인분 분량을 정합니다. 레시피, 조리법 템플릿, 재료별 분포, 기본값 순서로 찾습니다.
3. 분량(kg)에 재료 1kg당 배출계수를 곱합니다. 배출계수는 9단계로 나뉘어 있습니다.
4. 재료 전체 질량으로 조리 에너지와 음식물 쓰레기 처리 배출을 구해 더합니다.
5. 시뮬레이터는 1인분 값에 하루 이용자 수와 점심 일수(260일)를 곱해 1년 배출량을 구합니다.

```
1인분 CO₂e = Σ(재료 분량 kg × 재료 배출계수)            재료 분량 = 포함률 × 중앙값
           + 재료 질량 합 kg × 조리 에너지 MJ/kg × 연료 배출계수
           + 재료 질량 합 kg × 0.15 × 0.1756
```

계산은 모두 브라우저 안에서 합니다. 서버로 보내는 값은 없습니다.

## 계산에 쓰는 데이터

앱 안의 데이터는 JSON 하나(`window.PAYLOAD`)입니다. 공개 파일은 이 JSON의 같은 이름 항목과 형식이 같습니다. 아래 표의 '비공개'는 공개 데이터(`data/`)에 넣지 않았고 공개 라이선스 대상도 아니라는 뜻입니다.

| 항목 | 내용 | 공개 | 공개 파일 |
|---|---|---|---|
| `tokens` | 메뉴 이름을 나누는 단어. `[단어, 종류, 재료, 조리법, 조리 방식]` | 공개(제품명 단어 56개 제외) | [tokens.json](../data/dictionary/tokens.json) |
| `alias` | 단어 → 표준 재료 이름 | 공개 | [alias.json](../data/dictionary/alias.json) |
| `methods` | 단어 → `[조리법, 조리 방식]` | 공개 | [methods.json](../data/dictionary/methods.json) |
| `std_category` | 표준 재료 → 분류(육류, 채소 등) | 공개 | [std_category.json](../data/dictionary/std_category.json) |
| `rules` | 해석 규칙과 기준값 | 공개 | [rules.json](../data/dictionary/rules.json) |
| `factors` | 재료 1kg당 배출계수(9단계) | 공개 | [emission_factors.json](../data/emission_factors.json) |
| `parameters` | 조리·폐기·불확실성 파라미터 | 공개 | [parameters.json](../data/parameters.json) |
| `sources` | 출처 목록 | 공개(S012는 비공개 표시만) | [sources.json](../data/sources.json) |
| `recipes` | 메뉴별 재료 1인분 분량 분포 | 비공개 | 없음 |
| `core_index` | 수식어를 뺀 이름 → 레시피 이름 | 비공개 | 없음 |
| `templates` | 조리법별 재료 구성과 분량 분포 | 비공개 | 없음 |
| `global_qty` | 재료별 1인분 분량 분포(모든 레시피) | 비공개 | 없음 |
| `segments` | 세그먼트(연령·기관)별 분량 배율 | 비공개 | 없음 |
| `complete_segments` | 기본양념까지 빠짐없이 적은 조리지침서가 있는 세그먼트 목록 | 비공개 | 없음 |
| `corpus` | 기존 식단의 메뉴 빈도, 메뉴별 계산 결과, 대체값 | 비공개 | 없음 |
| `meta` | 내부 빌드 정보(건수·버전). 계산에 쓰지 않음 | 비공개 | 없음 |

분량 분포는 모두 `[포함률, 중앙값 g, p25 g, p75 g, 건수]` 배열입니다.

- 포함률: 그 메뉴(템플릿이면 그 조리법)의 조리지침서 가운데 이 재료가 들어간 비율(0~1).
- 중앙값, p25, p75: 1인분 분량(g)의 중앙값과 25%·75% 분위수.
- 건수: 분포를 만든 자료 수. 계산 엔진은 이 값을 읽지 않습니다.

비공개 항목의 모양은 아래와 같습니다.

**형식 예시(실제 값 아님)**

```json
{
  "recipes": {
    "예시메뉴국": {
      "n": 10,
      "segs": { "세그먼트A": 10 },
      "base": { "재료A": [1, 100, 80, 120, 10], "재료B": [0.5, 10, 5, 15, 5] },
      "seg": {}
    }
  },
  "core_index": { "예시메뉴국": "예시메뉴국" },
  "templates": {
    "예시조리법": {
      "n": 10, "n_complete": 5, "mode": "끓임",
      "slots": { "주재료": [100, 80, 120, 10], "부재료": [20, 10, 30, 10], "양념": [5, 3, 8, 10], "유지": null },
      "ings": { "재료A": [0.9, 100, 80, 120, 9] }
    }
  },
  "global_qty": { "재료A": [1, 50, 30, 70, 10] },
  "segments": {
    "기준세그먼트": { "scale": 1, "basis": "근거 설명", "src": "S0XX", "sigma": 0.1 },
    "세그먼트A": { "scale": 2.0, "basis": "근거 설명", "src": "S0XX", "sigma": 0.1 }
  },
  "complete_segments": ["세그먼트A"],
  "corpus": {
    "freq": { "예시메뉴국": 10 },
    "results": { "예시메뉴국": [1, 1.0, "국·찌개", "국"] },
    "method_prior": { "국": { "median": 1.0, "shares": { "production": 0.6, "processing": 0.1, "distribution": 0.1, "consumption": 0.1, "disposal": 0.1 }, "mass_g": 100, "n": 10 } },
    "weighted_median": 1.0
  }
}
```

- `recipes[이름].n`은 레시피의 근거 건수(코드에서는 '블록'이라고 부릅니다), `segs`는 세그먼트별 건수, `base`는 기준 세그먼트로 맞춘 분포, `seg`는 세그먼트 전용 분포입니다.
- `templates[조리법].slots`의 배열은 `[중앙값, p25, p75, 건수]`입니다. 엔진은 `주재료` 자리만 읽습니다.
- `corpus.results[메뉴]`는 `[계산 수준, 기준 세그먼트 1인분 CO₂e, 역할, 조리법]`입니다. 계산 수준은 2장의 1~4입니다.
- `corpus.freq[메뉴]`는 그 메뉴가 기존 식단에 나온 횟수입니다.
- `corpus.results`와 `corpus.freq`는 두 곳에 씁니다. 하나는 대체 메뉴 찾기(5-4절)입니다. 다른 하나는 메뉴 입력칸의 자동완성 목록입니다. 자동완성 목록은 계산 수준이 3 이하이고 이름에 `/`, `+`가 없는 메뉴를 `freq`가 큰 순서로 모은 것입니다.
- `corpus`에는 등급 함수용 구간(`menu_bounds`, `meal_bounds`)과 엔진이 읽지 않는 항목도 들어 있습니다.

## 1. 메뉴 이름 해석

### 1-1. 이름 정리

코드: engine.js `normalize`

1. 유니코드 NFC로 맞추고 공백을 모두 지웁니다.
2. `( )`, `[ ]`, `{ }`와 그 안의 글자를 지웁니다.
3. 장식 기호 `☆★♡♥※◎○●▶▷◆◇■□◈▲△▼▽*`를 지웁니다.
4. 이름 끝에 붙은 숫자·쉼표·점·빗금을 지웁니다(가격, 번호 등).
5. 앞뒤의 `-`, `~`, `·`, `.`을 지웁니다.

예: `소고기국밥(1,200)` → `소고기국밥`, `★김치볶음밥★` → `김치볶음밥`

레시피를 찾을 때도 이렇게 정리한 이름을 씁니다.

### 1-2. 단어 나누기

코드: engine.js `tokenize`

1. 기호 `( ) [ ] & * + / · , - _ ' " ~ ! ? . :`를 경계로 이름을 조각냅니다.
2. 조각마다 왼쪽부터, 그 자리에서 시작하는 사전(`tokens`) 단어 가운데 가장 긴 것을 고릅니다.
3. 맞는 단어가 없으면, 다음에 사전 단어가 시작되는 자리까지를 '미등록' 단어 하나로 묶습니다.

해석률(`coverage`)은 `1 − 미등록 글자 수 ÷ 전체 글자 수`를 소수 셋째 자리로 반올림한 값입니다. 전체 글자 수는 한글·영문·숫자만 셉니다. 미등록 글자 수는 미등록 조각의 글자를 모두 셉니다. 해석률은 결과에 함께 담기지만 배출량 계산에는 쓰지 않습니다.

| 단어 종류 | 공개판 개수 | 계산에서 하는 일 |
|---|---:|---|
| 재료 | 591 | `alias`에서 표준 재료를 찾습니다. |
| 조리법 | 80 | `methods`에서 조리법과 조리 방식을 찾습니다. |
| 수식어 | 215 | 매콤, 옛날 같은 말입니다. 레시피 이름을 찾을 때 뺍니다. |
| 양념수식 | 13 | 데리야키, 갈릭 같은 말입니다. 재료나 조리법으로는 쓰지 않습니다. |
| 제품명 | 0(내부판 56) | 레시피 이름을 찾을 때 뺍니다. 공개판에는 없습니다. |

### 1-3. 재료·조리법 읽기

코드: engine.js `parse`

**재료**: 단어가 `alias`에 있으면 그 표준 재료를 씁니다. 같은 재료는 한 번만 넣습니다.

**조리법**은 이 순서로 정합니다.

1. 단어가 `methods`에 있으면 조리법 후보입니다. 재료이기도 한 단어(불고기, 제육, 김치 등)는 '보조 후보', 나머지는 '주 후보'입니다. 같은 종류의 후보가 여럿이면 이름에서 뒤에 나온 단어를 씁니다.
2. `methods`에 없는 재료 단어는 끝부분을 봅니다. 긴 끝부분부터 2글자까지 줄여 가며 `methods`에 있는지 찾고, 있으면 주 후보로 씁니다. 예: 김치찌개 → 찌개, 닭갈비 → 갈비.
3. 주 후보가 있으면 주 후보를, 없으면 보조 후보를 씁니다.
4. 후보가 없고 재료에 단백질 재료(`protein_stds`)가 있으면 조리법과 조리 방식을 모두 '기타'로 둡니다.
5. 그래도 없으면 완제품 규칙(`product_std_method`)을 봅니다. 예: 우유 → 유제품·완제품, 사과 → 과일·무가열. 해당 재료가 여럿이면 과일이 아닌 것을 먼저, 그중 이름 뒤쪽에 나온 것을 씁니다.

**이름 자체가 고기를 뜻하는 단어**(`dual_protein_tokens`): 불고기, 제육, 설렁탕 같은 단어는 `alias`에서 특정 고기로 이어집니다(불고기 → 소고기, 제육 → 돼지고기). 같은 이름에 이런 단어가 아닌 단백질 재료가 따로 있으면, 그 재료와 다른 고기는 뺍니다. 예: 오리불고기는 '오리'가 있으므로 불고기가 뜻하는 소고기를 빼고 오리고기만 남깁니다.

`dual_protein_tokens`에 든 '갈비'는 `alias`에 없습니다. 그래서 재료로는 읽히지 않고 조리법(갈비·구이)으로만 쓰입니다.

**축종을 모르는 고기**: '고기'처럼 축종을 알 수 없는 재료(`육류(불명)`)는, 같은 이름에 돼지고기·소고기·닭고기·오리고기·양고기·육가공품이 있으면 뺍니다(`resolve`에서 처리).

공개 사전으로 해석한 예입니다.

| 메뉴 이름 | 단어 | 조리법 · 조리 방식 | 재료 |
|---|---|---|---|
| 소고기국밥 | 소고기(재료) + 국밥(조리법) | 국밥 · 끓임 | 소고기 |
| 시래기국 | 시래기(재료) + 국(조리법) | 국 · 끓임 | 건나물·묵나물 |
| 김치볶음밥 | 김치(재료 겸 조리법) + 볶음밥(조리법) | 볶음밥 · 볶음 | 김치·절임류 |
| 매콤제육볶음 | 매콤(수식어) + 제육(재료 겸 조리법) + 볶음(조리법) | 볶음 · 볶음 | 돼지고기 |
| 오리불고기 | 오리(재료) + 불고기(재료 겸 조리법) | 불고기 · 볶음 | 오리고기 |
| 돼지갈비찜 | 돼지갈비(재료) + 찜(조리법) | 찜 · 찜 | 돼지고기 |

### 1-4. 식물성 대체육 규칙

식물성 대체육은 검증된 배출계수가 없습니다(`emission_factors.json`에 없음). 그래서 대체육이 주재료인 메뉴는 계산에서 뺍니다.

1. 이름의 단어 가운데 `plant_signal`(식물성, 비건, 채식, 콩고기, 대체육 등)이 있으면 '식물성 신호가 있는 메뉴'로 봅니다. 단어 종류와 관계없이 모든 단어에서 찾습니다. 예를 들어 '콩고기'는 종류가 '재료'인 단어이지만 식물성 신호로 잡힙니다.
2. 이런 메뉴에서는 고기·해산물 재료를 모두 `식물성대체육` 하나로 바꿉니다. 고기·해산물은 분류가 육류·어패류인 재료와 `plant_replace_stds`(육가공품, 어묵·어육가공)입니다.
3. 분량을 정한 뒤(2장), 고기·해산물 재료 가운데 템플릿이 보탠 암묵 재료(`template-hidden`)와 보충 재료(`template-supplement`)는 버립니다. 레시피에 원래 들어 있던 고기·해산물은 이름에 없더라도 버리지 않습니다. 이것들은 나머지 고기·해산물과 함께 `식물성대체육` 하나로 합칩니다. 포함률은 큰 값, 분량(중앙값·p25·p75)은 합을 씁니다.
4. `식물성대체육`의 `포함률 × 중앙값`이 `10 g × 세그먼트 배율`(`plant_exclude_min_g`) 이상이면 메뉴 전체를 '계산 제외'로 둡니다. 배출량은 0이고, 화면에는 "식물성 대체육 메뉴 · 계산 제외"라고 나옵니다.
5. 그보다 적으면 `식물성대체육`만 빼고 나머지 재료로 계산합니다.

예: 콩고기불고기 → 콩고기(식물성대체육) + 불고기(소고기) → 소고기가 식물성대체육으로 바뀜 → 계산 제외.

## 2. 1인분 재료 분량

분량은 engine.js `resolve`가 정합니다. 찾은 자료에 따라 계산 수준(`tier`)이 1~4로 나뉩니다.

| 계산 수준 | 조건 | 분량 출처 | 화면 표시(메뉴별 비교 탭) |
|---|---|---|---|
| 1 | 레시피를 찾음 | 레시피의 재료별 분포 | "레시피 그대로 계산했어요" 등 |
| 2 | 레시피는 없고 조리법 템플릿이 있음(재료를 못 읽어도 됨) | 조리법 템플릿 | 표시 없음 |
| 3 | 레시피·템플릿은 없지만 재료를 읽음 | 재료별 전체 분포, 없으면 기본값 | "재료만 보고 어림했어요" |
| 4 | 레시피·템플릿이 없고 재료도 읽지 못함 | 없음 | "모르는 메뉴예요" |

대체값(3-5절)을 쓴 메뉴는 계산 수준과 관계없이 "모르는 메뉴예요"가 나옵니다.

### 2-1. 레시피 찾기

1. **같은 이름**(`exact`): 정리한 이름이 `recipes`에 그대로 있으면 씁니다.
2. **수식어를 뺀 이름**(`core`): 수식어·제품명 단어를 뺀 이름(`coreKey`)으로 `core_index`를 찾습니다. 예: 매콤제육볶음 → 제육볶음.
3. **레시피 묶음**(`family`): 레시피 이름이 입력 이름으로 끝나는 레시피가 3개(`family_min`) 이상이면 묶어서 씁니다. 입력 이름이 2글자 이상일 때만 봅니다.
4. **이름에 든 레시피**(`contained`): 입력 이름이 어떤 레시피 이름으로 끝나면 그 레시피를 씁니다. 입력 이름은 4글자 이상, 레시피 이름은 3글자(`contained_min_len`) 이상이어야 합니다. 여럿이면 가장 긴 이름을, 길이가 같으면 건수가 많은 것을 고릅니다.

화면 표시는 1·2번이 "레시피 그대로 계산했어요", 3번이 "비슷한 레시피로 계산했어요", 4번이 "이름에 든 메뉴의 레시피로 계산했어요"입니다.

### 2-2. 수준 1: 레시피 분량

- 기본은 `분량 = 레시피 base 분포 × 세그먼트 배율`입니다(근거 표시 `recipe-base`).
- 레시피에 앱이 쓰는 세그먼트 전용 분포(`seg`)가 있으면 배율 없이 그 분포를 씁니다(`recipe-seg`). 지금 DB에는 전용 분포가 없어서 이 경로는 쓰이지 않습니다.
- 레시피 묶음(`family`)은 묶인 레시피들을 건수(`n`)로 가중해 합칩니다.

```
포함률_j = Σ(n_r × 포함률_r,j) ÷ Σ n_r        (합은 묶인 레시피 전체, 재료가 없으면 0으로 셈)
중앙값_j, p25_j, p75_j = 재료 j가 있는 레시피들의 값을 n_r로 가중한 중앙값
분량 = 위 값 × 세그먼트 배율                  (근거 표시 recipe-family)
```

- 이름에 든 레시피(`contained`)를 쓸 때, 이름에는 있지만 그 레시피에 없는 재료는 따로 보탭니다. 분량은 템플릿 → 재료별 전체 분포 → 30 g(20~45 g) 순서로 찾고, 포함률은 1입니다. 식물성 신호가 있고 레시피에 고기·해산물이 있으면 `식물성대체육`은 따로 보태지 않습니다(1-4절 3번에서 합쳐지기 때문).
- **기본양념 보충**: 일부 세그먼트의 조리지침서는 기본양념 같은 재료를 적지 않습니다. 코드의 근거 설명 문구에는 기준 세그먼트(지역아동센터) 지침서가 그렇다고 적혀 있습니다. 그래서 레시피 근거 가운데 `complete_segments`에서 온 것이 하나도 없고 그 조리법의 템플릿이 있으면, 템플릿에서 아래 재료를 보탭니다(`template-supplement`).
  - 대상: 분류가 양념·당류·유지인 재료, 쌀·잡곡(`grain_like`), 육수·물·대파·마늘·양파·생강(`complete_extra`)
  - 조건: 템플릿 포함률 0.3(`presence_min`) 이상, 아직 없는 재료
  - 분량: 템플릿 분포 × 배율, 포함률은 템플릿 값 그대로

### 2-3. 수준 2: 조리법 템플릿

레시피가 없으면 조리법 템플릿으로 분량을 정합니다. 먼저 이름에서 읽은 재료를 자리별로 나눕니다(`slotOf`). 위 줄부터 차례로 봅니다.

| 자리 | 해당 재료 |
|---|---|
| 유지 | `oil_stds`(참기름, 들기름, 식용유, 버터, 생크림) |
| 양념 | 분류가 양념·당류·유지인 재료 |
| 수분 | `water_stds`에 들고 분류가 양념·당류·유지가 아닌 재료(지금은 차·물). 육수·스톡은 분류가 양념이라 '양념' 자리로 갑니다 |
| 식재료 | 나머지 |

양념·유지·수분은 아래에서 같은 규칙으로 다룹니다. 그래서 육수·스톡이 어느 자리에 들어가도 계산값은 같습니다.

분량을 찾기 전에 식재료 목록을 줄이는 경우가 있습니다. 조리법이 완제품류(`product_methods`: 견과, 과일, 과자, 디저트, 떡, 빵, 유제품, 음료)이면서 과일이 아니고, 식재료 가운데 `product_cats`(가공식품, 견과, 곡류, 면류, 유제품, 음료) 분류가 있으면, 그중 이름 뒤쪽의 하나만 식재료로 남깁니다.

남은 식재료 가운데 이름에서 **마지막에 나온 것**을 주재료로 봅니다. 이름에 적힌 재료는 모두 포함률 1로 넣고, 분량은 아래 순서로 찾습니다. 모든 분량에 세그먼트 배율을 곱합니다.

| 재료 | 분량을 찾는 순서 |
|---|---|
| 주재료, 템플릿에 있음 | 템플릿의 그 재료 분포 |
| 주재료, 템플릿에 없음 | 템플릿의 '주재료' 자리 분포 → 재료별 전체 분포 → 30 g(20~45 g) |
| 그 밖의 식재료 | 템플릿의 그 재료 분포 → 재료별 전체 분포 → 15 g(10~25 g) |
| 양념·유지·수분 | 템플릿의 그 재료 분포 → 재료별 전체 분포 → 3 g(2~5 g) |

`slot_exempt_methods`(짜장면)는 주재료가 템플릿에 없을 때 '주재료' 자리를 쓰지 않고 '그 밖의 식재료' 규칙을 따릅니다.

이어서 아래를 처리합니다.

1. **암묵 재료**(`template-hidden`): 이름에는 없지만 그 조리법에 자주 들어가는 재료를 보탭니다. 템플릿 포함률 0.3 이상인 재료를 포함률만큼(`포함률 × 분량`) 넣습니다. 단, 주재료가 단백질 재료이면 다른 단백질 재료는 보태지 않습니다. 완제품류 조리법에서는 이 처리를 건너뜁니다.
2. **주재료를 모를 때**(`template-unknown-main`): 이름에서 식재료를 못 읽었고, 암묵 재료에도 식재료가 없고, 템플릿에 '주재료' 자리 분포가 있으면, 그 분량을 `기타채소`로 넣습니다.

단백질 재료는 분류가 육류·어패류이거나 `protein_like_stds`(만두류, 식물성대체육, 어묵·어육가공, 육가공품, 조리완제품, 튀김·완제품)에 드는 재료입니다.

### 2-4. 수준 3: 재료만 보고 어림

조리법 템플릿이 없으면 이름에서 읽은 재료마다 재료별 전체 분포(`global_qty`)를 씁니다. 없으면 30 g(20~45 g)을 넣습니다. 포함률은 1이고 세그먼트 배율을 곱합니다(`global-std`).

### 2-5. 수준 4: 읽지 못한 메뉴

레시피도 조리법 템플릿도 없고 재료도 하나도 읽지 못하면 분량이 없습니다. 이때 배출량은 3-5절의 대체값 규칙을 따릅니다. 조리법 템플릿이 있으면 재료를 못 읽어도 수준 2로 계산합니다(2-3절 '주재료를 모를 때').

### 2-6. 코드에 적힌 기본값

| 쓰는 곳 | 중앙값 | p25~p75 |
|---|---:|---:|
| 주재료 또는 재료별 분포가 없는 재료(수준 1~3) | 30 g | 20~45 g |
| 그 밖의 식재료(수준 2) | 15 g | 10~25 g |
| 양념·유지·수분(수준 2) | 3 g | 2~5 g |

### 2-7. 세그먼트 배율

- DB의 분량 분포(`recipes.base`, `templates`, `global_qty`)는 모두 기준 세그먼트(지역아동센터) 1인분으로 맞춰 둔 값입니다.
- 세그먼트마다 배율(`scale`), 근거(`basis`), 출처(`src`), 불확실성(`sigma`)을 적어 둡니다. 기준 세그먼트의 배율은 1입니다.
- 앱은 언제나 **산업체오피스**(성인 구내식당) 세그먼트로 계산합니다. dash.js와 app.js에 상수로 적혀 있습니다. 화면의 "1인분 · 성인 구내식당 기준"이 이 뜻입니다.
- 배율은 수준 1~3의 분량(세그먼트 전용 분포는 제외), 식물성 대체육 기준 10 g, 조리법 대체값(3-5절)에 곱합니다.
- 배율 값은 내부 자료로 만들었고, 공개 데이터(`data/`)에는 넣지 않았습니다.

## 3. 배출량 계산

배출량은 engine.js `emissions`가 구합니다. 기본 연료는 도시가스입니다(`cooking_fuel_default`).

### 3-1. 재료 배출

```
q_i = 포함률_i × 중앙값_i ÷ 1000                     (kg)
E_i,단계 = q_i × EF_i,단계                            (단계 9개)
```

- 분량은 평균이 아니라 **중앙값**에 포함률을 곱한 값입니다.
- 배출계수 `EF`는 `factors[재료]`입니다. 표에 없는 재료는 `기타채소` 계수를 씁니다.
- 배출계수는 9단계로 나뉩니다. 앞의 8단계(`luc`~`losses`)는 Poore & Nemecek(2018)의 구분입니다. 마지막 `disposal`(폐기)은 환경성적표지(S005) 제품 값의 폐기 단계를 담는 칸입니다. 지금 이 칸에 값이 있는 재료는 11종입니다(환경성적표지 값을 쓴 `direct_product` 10종과 김치·절임류). 나머지는 0입니다.
- 화면에서는 9단계를 다섯 단계로 묶어 보여 줍니다.

| 화면 단계 | 계산에 들어가는 값 |
|---|---|
| 생산 | `luc`(토지 이용 변화) + `farm`(농장) + `feed`(사료) |
| 가공 | `processing` |
| 유통 | `transport`(운송) + `retail`(소매) + `packaging`(포장) + `losses`(손실) |
| 조리 | 조리 에너지(3-2절) |
| 폐기 | `disposal`(계수에 든 폐기 단계) + 음식물 쓰레기 처리(3-3절) |

배출계수를 만든 방법은 재료마다 다릅니다. 자세한 근거는 `emission_factors.json`의 `basis`, `note`, `components` 칸과 [데이터 설명서](DATA.md)에 있습니다.

| 품질 등급 | 재료 수 | 만든 방법(대표 예) |
|---|---:|---|
| `direct` | 47 | 출처 값을 그대로 씀. 국내 소·돼지·닭고기는 자급률로 국내산과 수입산을 섞음(아래) |
| `direct_product` | 10 | 환경성적표지 인증 제품(S005)의 kg당 중앙값 + P&N 유통 단계 대용 |
| `group_mean` | 41 | 한국 식품군 평균(S003)을 P&N 단계 비율로 나눔 |
| `proxy` | 29 | 비슷한 식품의 값으로 대신함(예: 오리고기 → P&N 가금류) |
| `pending` | 3 | 자료를 아직 확보하지 못한 잠정값 |

소·돼지·닭고기는 이렇게 섞습니다.

- 국내산 비중은 2024 자급률입니다. 소고기 42%, 돼지고기 71%, 닭고기 75%입니다. 국내산 값은 기후솔루션(S002)의 단계별 값입니다.
- 소고기 수입분은 S002의 미국·호주·뉴질랜드 값을 섞습니다. 비중은 `imported_beef_shares`(미국 0.47, 호주 0.47, 뉴질랜드 0.03)이고, 합이 0.97이라 1로 맞춰 씁니다.
- 돼지고기·닭고기 수입분은 P&N(S001) 값을 대신 씁니다.

### 3-2. 조리 에너지

```
Q = Σ q_i                                            (모든 재료의 질량 합, kg)
E_조리 = Q × MJ(조리 방식) × EF_연료
EF_도시가스 = 0.0561 kg CO₂e/MJ                       (천연가스 56,100 kg/TJ, S008)
EF_전기     = 0.4173 kg CO₂e/kWh ÷ 3.6 = 0.1159 kg CO₂e/MJ   (S009)
```

- `Q`에는 양념·유지뿐 아니라 육수·스톡과 물(차·물)도 들어갑니다. 레시피·템플릿이나 기본양념 보충(2-2절)으로 이 재료가 들어오면 함께 더합니다.
- `parameters.json`의 `cook_mj_per_kg` 비고에는 '재료 질량(물 제외) 기준 적용'이라고 적혀 있습니다. 코드는 물을 빼지 않습니다.

조리 방식은 1-3절에서 읽은 값이고, 없으면 '기타'입니다. 조리 방식별 에너지는 `cook_mj_per_kg`(S006, 가정용 조리 원단위)입니다.

| 조리 방식 | MJ/kg 재료 | 재료 1kg당 kg CO₂e(도시가스) | 재료 1kg당 kg CO₂e(전기) |
|---|---:|---:|---:|
| 끓임, 조림, 찜, 데침, 기타 | 3.5 | 0.1964 | 0.4057 |
| 볶음, 부침, 튀김 | 7.5 | 0.4208 | 0.8694 |
| 구이 | 8.5 | 0.4769 | 0.9853 |
| 무가열, 완제품 | 0 | 0 | 0 |

전기의 MJ당 배출계수는 도시가스의 약 2.07배입니다. 그래서 시뮬레이터에서 조리 연료를 전기로 바꾸면 배출이 늘어납니다.

### 3-3. 음식물 쓰레기

```
E_쓰레기 = Q × 0.15 × 0.1756                          (= Q × 0.02634)
```

- 0.15는 조리량 대비 음식물 쓰레기 비율(`waste_rate`, S011)입니다. 코드는 조리량 대신 재료 질량 합 `Q`(물·육수 포함, 3-2절)를 씁니다.
- 0.1756 kg CO₂e/kg은 퇴비화 처리 계수(`waste_treatment_kgco2e_per_kg`, S007)입니다. 습중량 1kg당 CH₄ 4 g × 28 + N₂O 0.24 g × 265 = 175.6 g입니다(GWP는 IPCC AR5 100년 값).
- 여기서 더하는 것은 처리 배출뿐입니다. 버려지는 음식의 재료를 생산한 배출은 재료 배출(3-1절)에 이미 들어 있습니다.

### 3-4. 합계

```
생산 = Σ q_i × (luc + farm + feed)
가공 = Σ q_i × processing
유통 = Σ q_i × (transport + retail + packaging + losses)
조리 = E_조리
폐기 = Σ q_i × disposal + E_쓰레기
1인분 CO₂e = 생산 + 가공 + 유통 + 조리 + 폐기
재료 질량(화면의 '재료 ○○g') = Q × 1000
```

조리법 대체값을 쓴 메뉴는 화면의 재료 질량이 다릅니다(3-5절).

### 3-5. 대체값

분량으로 계산할 수 없는 메뉴는 아래 값을 씁니다.

| 경우 | 조건 | 쓰는 값 | 화면 |
|---|---|---|---|
| 식물성 대체육 | 1-4절 규칙 | 0(계산 제외) | "식물성 대체육 메뉴 · 계산 제외" |
| 조리법 대체값 | 아래 네 조건을 모두 만족 | 기존 식단에서 그 조리법 메뉴들의 배출량 중앙값 × 세그먼트 배율 | "모르는 메뉴예요" + 안내 문구(문구에는 전체 가중 중앙값이 나옴) |
| 전체 가중 중앙값 | 수준 4이고, 이름에 한글이 있고, 식단이 아닌 문구가 아님 | 기존 식단 데이터의 가중 중앙값(`corpus.weighted_median`) | "모르는 메뉴예요" + 안내 문구 |
| 식단이 아닌 문구 | 수준 4이고 위 조건에 맞지 않음 | 0 | "모르는 메뉴예요" |

**조리법 대체값의 조건**

1. 계산 수준이 2입니다.
2. 이름에서 식재료(자리가 '식재료'인 재료)를 하나도 읽지 못했습니다.
3. 정한 분량 가운데 식재료의 `포함률 × 중앙값` 합이 20 g 미만입니다. 배율을 곱한 뒤의 값으로 비교합니다.
4. 그 조리법의 대체값(`corpus.method_prior[조리법]`)이 있습니다.

조리법 대체값을 쓰면 이렇게 계산합니다.

- 합계를 `method_prior.shares`의 비율로 생산·가공·유통·조리·폐기에 나눕니다.
- 쓰레기 처리 배출(`waste`)은 따로 구하지 않고 0으로 둡니다. 조리 몫은 연료와 관계없이 같습니다.
- 화면의 '재료 ○○g'는 `Q`가 아니라 `method_prior.mass_g × 세그먼트 배율`입니다.

**식단이 아닌 문구**: 이름에 '행사·연휴·적용·REF·없음·휴무·방학·명절' 가운데 하나가 들어 있으면 식단이 아닌 문구로 보고 0을 씁니다. 이 규칙은 수준 4에만 적용됩니다. 그래서 사전 단어가 든 문구는 수준 3으로 계산됩니다(8장).

두 대체값(조리법별 중앙값, 전체 가중 중앙값)은 내부 식단 자료로 만들었고, 공개 데이터(`data/`)에는 넣지 않았습니다. 앱 화면의 안내 문구는 전체 가중 중앙값을 '중간값'이라고 부릅니다.

### 3-6. 계산 예

아래는 공식을 보여 주려고 만든 예입니다. **분량은 설명용 가정이고 실제 레시피 분량이 아닙니다.** 1인분에 소고기 100 g만 들어간 끓인 요리를 도시가스로 조리했다고 가정합니다. 소고기 배출계수는 공개 값 41.3394 kg CO₂e/kg입니다.

| 유통 | 0.1 × (0.359 + 0 + 0 + 0) | 0.0359 |

## 4. 불확실성과 '가능한 범위'

### 4-1. 어디에 보이나

- '어떻게 계산하나요?' 탭의 예시 표 합계 줄에 "가능한 범위 ○~○ kg CO₂e"로 나옵니다. 교육 모듈에 나오는 두 메뉴(기본은 소고기국밥과 시래기국)를 예시로 쓰며, 이 두 메뉴에만 계산합니다.
- 교육 모듈도 두 메뉴의 범위를 같은 방법으로 계산하지만 화면에는 보여 주지 않습니다.
- '메뉴별 CO₂e 비교' 탭, '메뉴 바꾸기 비교' 탭, 시뮬레이터에는 범위가 없습니다.

### 4-2. 방법

engine.js `monteCarlo`의 몬테카를로 시뮬레이션입니다.

1. 2,000번(`mc_iterations`) 반복합니다.
2. 난수는 mulberry32 방식 생성기에 시드 12345를 고정해 만듭니다. 그래서 같은 메뉴는 늘 같은 범위가 나옵니다. 정규분포 난수는 Box–Muller 방법으로 만듭니다.
3. 불확실한 값마다 평균이 1인 로그정규 배수를 곱합니다.

```
LN(σ) = exp(σ·z − σ²/2),  z ~ 표준정규분포
```

4. 반복마다 아래처럼 1인분 값을 다시 계산합니다.

```
반복마다 한 번 뽑는 배수:  S = LN(0.15),  C = LN(0.4),  W = LN(0.3),  T = LN(0.5)
                          B_j = LN(σ_EF,j)   (재료 종류 j마다 하나)
재료마다 새로 뽑는 배수:    LN(σ_q,i)

재료 i를 넣을지: 포함률_i < 1이면 확률 포함률_i로 넣거나 뺌
m_i = 중앙값_i ÷ 1000 × LN(σ_q,i) × S                 (세그먼트 전용 분포면 S 대신 1)
E = Σ m_i × EF총계_i × B_j(i)
  + (Σ m_i) × MJ(조리 방식) × C × EF_연료
  + (Σ m_i) × 0.15 × W × 0.1756 × T
```

- `B_j`는 같은 반복 안에서 같은 재료에 똑같이 적용됩니다.
- 분량의 σ는 분포의 사분위 범위로 정합니다. `σ_q = min(1, ln(p75 ÷ p25) ÷ 1.349)`이고, p75가 p25보다 크지 않거나 p25가 0 이하이면 0.35(`sigma_qty_default`)입니다. 1.349는 표준정규분포의 사분위 범위입니다.
- 대체값으로 계산한 메뉴는 `E = 대체값 × LN(σ)`입니다. σ는 조리법 대체값이 0.6, 전체 가중 중앙값이 1.0입니다(코드 상수).
- 연료 배출계수는 흔들지 않습니다. 배출계수는 단계별 값이 아니라 총계(`total`)를 흔듭니다.

5. 2,000개 값을 정렬해 10번째 백분위(p10)와 90번째 백분위(p90)를 고릅니다. 위치는 `round(비율 × (N − 1))`번째입니다.

| 흔드는 값 | σ(로그정규) | 파라미터 |
|---|---:|---|
| 재료 분량 | 분포별 계산, 기본 0.35 | `sigma_qty_default` |
| 세그먼트 배율 | 0.15 | `sigma_scale` |
| 배출계수(`direct_product`) | 0.2 | 재료별 `sigma`(`emission_factors.json`) |
| 배출계수(`direct`) | 0.3 | 재료별 `sigma` |
| 배출계수(`group_mean`) | 0.35 | 재료별 `sigma` |
| 배출계수(`proxy`) | 0.45 | 재료별 `sigma` |
| 배출계수(`pending`) | 0.6 | 재료별 `sigma` |
| 조리 에너지 | 0.4 | `cook_mj_per_kg.sigma` |
| 음식물 쓰레기 비율 | 0.3 | `waste_rate.sigma` |
| 쓰레기 처리 계수 | 0.5 | `waste_treatment_kgco2e_per_kg.sigma` |

배출계수의 σ는 `parameters.json`의 `sigma_by_quality`가 아니라 `emission_factors.json`에 재료마다 적힌 `sigma`를 읽습니다. 지금은 130종 모두 `sigma_by_quality`의 품질별 값과 같아서 위 표처럼 등급별로 정리할 수 있습니다.

### 4-3. 읽을 때 주의할 점

- 화면의 합계는 3장의 결정값입니다. 몬테카를로의 중앙값이 아닙니다. 그래서 합계가 범위의 한가운데에 있지 않을 수 있습니다.
- 배수의 평균이 1이고 포함 확률이 포함률과 같으므로, 반복 결과의 기댓값은 결정값과 같습니다.
- σ 값은 잠정 가정입니다. `sigma_by_quality`의 비고에 "출처 1개 계수 ±30% 잠정"을 로그정규 σ로 바꿨다고 적혀 있습니다.

|---|---|
| 재료 배출 | 재료별 9단계 배출의 합. 대체값 메뉴는 `합계 − 조리 − 쓰레기 처리`를 '가공식품·양념'에 넣음 |
| 조리(도시가스) | 도시가스로 계산한 조리 배출 |
| 조리(전기) | 전기로 다시 계산한 조리 배출. 조리법 대체값 메뉴는 도시가스 값과 같음 |
| 쓰레기 처리 | 3-3절의 `E_쓰레기`. 조리법 대체값 메뉴는 0 |

조리법 대체값 메뉴는 3-5절에서 조리 몫을 연료와 관계없이 나눕니다. 그래서 연료를 전기로 바꿔도 이 메뉴는 달라지지 않습니다. 재생에너지를 고르면 조리 몫이 0이 됩니다. 기준 식단에는 이런 메뉴가 없어서 예시 결과에는 영향이 없습니다.

재료 배출은 재료 분류에 따라 일곱 묶음으로 나눠 그래프에 씁니다.

| 묶음 | 재료 |
|---|---|
| 소고기 | 소고기 |
| 돼지·닭 등 다른 고기 | 분류가 육류인 재료(소고기 제외), 육가공품 |
| 생선·달걀·유제품 | 분류가 어패류·난류·유제품인 재료 |
| 밥·곡류·면 | 분류가 곡류·면류인 재료 |
| 채소·과일·콩 | 분류가 채소·과일·버섯·해조류·두류·견과인 재료 |
| 가공식품·양념 | 그 밖의 재료 |
| 조리 에너지·음식물 쓰레기 | 조리 배출 + 쓰레기 처리 배출 |

메뉴의 고기 분류는 재료로 정합니다. 소고기가 있으면 '소고기', 없고 돼지고기·육가공품이 있으면 '돼지고기', 없고 닭고기·오리고기가 있으면 '닭·오리'입니다. 고기 메뉴에는 대체 메뉴(5-4절)를 하나 정해 둡니다.

양고기나 `육류(불명)`만 읽힌 메뉴는 세 고기 막대 어디에도 속하지 않습니다. 그래서 막대를 움직여도 바뀌지 않습니다. 기준 식단에는 이런 메뉴가 없습니다.

### 5-3. 조절 막대

| 막대 | 범위(간격) | 기본값 | 계산에서 하는 일 |
|---|---|---|---|
| 하루 이용자 수 | 100~3,000명(50) | 500명 | 1년 합계에 곱함. 지금 식단과 바꾼 식단에 같이 적용 |
| 바뀌는 데 걸리는 기간 | 0~12개월(1) | 0(바로) | 1년 합계의 효과 비율 F를 정함(5-6절) |
| 소고기 메뉴 | 0~100%(5) | 100%(지금처럼) | 줄인 비율 `s = (100 − 값) ÷ 100`만큼 대체 메뉴로 바꿈 |
| 돼지고기 메뉴 | 0~100%(5) | 100% | 위와 같음(돼지고기·육가공품) |
| 닭·오리 메뉴 | 0~100%(5) | 100% | 위와 같음 |
| 고기 없는 날 | 주 0~5회(1) | 0 | 한 끼 평균의 `v ÷ 5`를 고기 없는 날 식단으로 바꿈 |
| 1인분 배식량 | 80~120%(5) | 100% | 재료·조리·쓰레기 처리 배출 모두에 `k = 값 ÷ 100`을 곱함 |
| 음식물 쓰레기 줄이기 | 0~50%(5) | 0 | 쓰레기 처리 배출에만 `1 − 값 ÷ 100`을 곱함 |
| 조리 에너지 | 도시가스·전기·재생에너지 | 도시가스 | 조리 배출을 도시가스 값, 전기 값, 0 가운데 하나로 바꿈 |

### 5-4. 대체 메뉴 고르는 규칙

고기 메뉴를 줄이면 그 자리를 '같은 역할의 대체 메뉴'가 채운다고 봅니다. '메뉴 바꾸기 비교' 탭의 추천 목록도 같은 규칙을 씁니다. 코드는 dash.js의 `g`(역할)와 `y`(후보 찾기)입니다.

**메뉴 역할**은 조리법으로 정합니다. 위에서부터 차례로 봅니다.

| 순서 | 조리법 | 역할 |
|---|---|---|
| 1 | `roles.kimchi` | 김치 |
| 2 | `roles.rice` | 밥 |
| 3 | `roles.soup` | 국·찌개 |
| 4 | `roles.noodle` | 면 |
| 5 | `roles.snack` | 간식·후식 |
| 6 | 볶음, 조림, 찜, 구이, 튀김, 전 | 단백질 재료가 있으면 주찬, 없으면 부찬 |
| 7 | `roles.main` | 주찬 |
| 8 | `roles.side` | 부찬(잡채에 단백질 재료가 있으면 주찬) |
| 9 | 그 밖 | 단백질 재료가 있으면 주찬, 없으면 기타 |

여기서 단백질 재료는 `protein_stds` 또는 `protein_like_stds`에 드는 재료입니다.

**대체 메뉴 후보**는 기존 식단 데이터의 메뉴 목록(`corpus.results`, 비공개)에서 찾습니다.

1. 원래 메뉴의 역할이 김치·기타이거나, 대체값으로 계산한 메뉴이면 찾지 않습니다.
2. 원래 메뉴 값을 세그먼트 배율로 나눠 기준 세그먼트 값으로 바꿉니다. 이 값이 0.15 kg CO₂e 미만이면 찾지 않습니다.
3. 아래 조건을 모두 만족하는 메뉴만 후보가 됩니다.
   - 계산 수준 1(레시피)로 계산된 메뉴입니다.
   - 역할이 원래 메뉴와 같습니다.
   - 기준 세그먼트 값이 0.05 이상이고, 원래 메뉴 값의 절반 이하입니다.
   - 기존 식단에 3번 이상 나왔습니다(`corpus.freq`).
   - 원래 메뉴와 이름이 다르고, 이름에 `/`, `&`, `+`가 없습니다.
4. 조리법이 같은 후보를 먼저, 그다음 자주 나온 순서로 줄 세웁니다. 조리법이 같은 후보가 하나라도 있으면 그것만 봅니다.
5. 앞에서부터 최대 300개를 살펴봅니다. 수식어를 뺀 이름이 같은 후보는 하나만 남깁니다. 원래 메뉴에 단백질 재료가 있으면 단백질 재료가 있는 후보만 받습니다.
6. 후보를 산업체오피스 1인분으로 다시 계산해, 원래 메뉴보다 값이 작은 것만 받습니다. 최대 5개까지 모읍니다.

시뮬레이터는 이 가운데 **소고기가 없는 첫 번째 메뉴**를 대체 메뉴로 씁니다. 대체 메뉴가 없으면 그 메뉴는 막대를 움직여도 바뀌지 않습니다.

### 5-5. 한 끼 평균

설정 `c`에서 메뉴 `m` 하나의 1인분 배출(`lt`)은 이렇습니다.

```
조리_m(c)  = 도시가스면 조리(도시가스), 전기면 조리(전기), 재생에너지면 0
쓰레기_m(c) = 쓰레기 처리_m × (1 − 쓰레기 감축률)
E_m(c) = (재료 배출_m + 조리_m(c) + 쓰레기_m(c)) × k
```

하루 식단 `d`의 1인 한 끼 배출(`rt`)은 고기 메뉴를 줄인 비율만큼 대체 메뉴와 섞은 값입니다.

```
E_d(c) = Σ_m [ (1 − s_m) × E_m(c) + s_m × E_대체(m)(c) ]
s_m = 그 메뉴 고기 분류의 줄인 비율 (고기 메뉴가 아니거나 대체 메뉴가 없으면 0)
```

20끼 전체의 한 끼 평균(`ct`)은 이렇습니다.

```
Ē(c) = (1/20) × Σ_d E_d(c)
고기 없는 날이 주 v회이면:
Ē(c) = (1 − v/5) × Ē(c) + (v/5) × E_고기없는날(c)
```

고기 없는 날 식단에는 고기 메뉴 줄이기를 적용하지 않습니다. 배식량, 쓰레기 감축, 조리 연료는 적용합니다. 줄이기는 특정 날짜를 고르는 방식이 아니라, 모든 해당 메뉴를 같은 비율로 섞는 방식입니다.

### 5-6. 1년 합계와 바뀌는 기간

dash.js `gt` 안에서 계산합니다.

```
Y0 = Ē(기본 설정) × 하루 이용자 수 × 260          (지금 식단)
Yt = Ē(현재 설정) × 하루 이용자 수 × 260          (바뀐 식단이 자리 잡은 뒤)
f_t = min(1, (t − 0.5) ÷ R),  t = 1…12            (R = 바뀌는 데 걸리는 개월 수, R = 0이면 f_t = 1)
F = (f_1 + … + f_12) ÷ 12
Y1 = Y0 + F × (Yt − Y0)                           (첫해 바꾼 식단)
1년 동안 줄어드는 CO₂e = Y0 − Y1,  비율 = (Y0 − Y1) ÷ Y0
```

- 260은 52주 × 5일입니다.
- '기본 설정'은 모든 막대가 기본값인 상태입니다. 하루 이용자 수만은 두 식단에 현재 값을 같이 씁니다. 그래서 이용자 수만 바꾸면 줄어드는 양은 0입니다.
- f_t는 각 달의 가운데 시점에서 효과가 직선으로 커진다고 본 값입니다.

| 바뀌는 기간 R | 0(바로) | 3개월 | 6개월 | 12개월 |
|---|---:|---:|---:|---:|
| 첫해 효과 비율 F | 1 | 0.875 | 0.75 | 0.5 |

- 누적 그래프: 지금 식단은 매달 `Y0 ÷ 12`, 바꾼 식단은 매달 `(Y0 + f_t × (Yt − Y0)) ÷ 12`를 더합니다.
- 재료군별 막대: 7개 묶음마다 같은 식으로 1년 값을 구합니다.
- 줄어드는 양의 절댓값이 0.5 kg 미만이면 0으로 표시합니다.

### 5-7. 결과 카드의 환산

| 표시 | 계산 |
|---|---|
| 승용차로 달리면 | `1000 × (Y0와 Y1 차이의 절댓값) ÷ 141.3` km (S013) |
| 소고기국밥으로 치면 | `(Y0와 Y1 차이의 절댓값) ÷ 소고기국밥 1인분 CO₂e` 그릇 |
| 1인 한 끼 평균 | `Ē(기본 설정)` → `Ē(현재 설정)` kg CO₂e. 바꾼 쪽은 바뀌는 기간과 관계없이 자리 잡은 뒤의 값 |

소고기국밥 1인분 값은 3장의 방법으로 계산한 산업체오피스 값입니다. 1만 이상인 숫자는 "만" 단위로 줄여 씁니다.

### 5-8. 한 달 식단 달력

코드: rolehub.js `renderMonth`

- 칸마다 그날의 1인 한 끼 배출 `E_d(현재 설정)`을 보여 줍니다. 값이 바뀐 칸에는 기본 설정 값을 줄을 그어 함께 씁니다.
- 고기 없는 날은 요일에 고르게 놓습니다. 주 1회는 수요일, 2회는 화·목, 3회는 월·수·금, 4회는 월·화·목·금, 5회는 매일입니다. 그 칸은 고기 없는 날 식단 값입니다.
- 대체 메뉴 옆의 퍼센트는 그 메뉴를 바꾸는 비율 `s_m`입니다. 100%로 모두 바꾸면 퍼센트 없이 원래 메뉴에 줄을 긋고 흐리게 보여 줍니다.
- 칸 막대 색은 1.6 kg 미만 초록, 1.6~2.5 kg 주황, 2.5 kg 이상 빨강입니다.
- 위쪽 요약의 '1인 한 끼 평균'과 '1년 효과'는 대시보드와 같은 식(5-5, 5-6절)으로 구합니다. 고기 없는 날을 특정 요일에 놓는 달력과 달리 평균은 `v/5` 비율로 섞으므로, 20칸 값을 단순 평균한 값과 조금 다를 수 있습니다.
- '한 달 식당 전체'는 `Ē(현재 설정) × 20끼 × 하루 이용자 수`입니다.

## 6. 교육 모듈의 숫자

교육 모듈은 두 메뉴(기본: 소고기국밥, 시래기국)를 3장의 방법으로 계산합니다. 두 메뉴 가운데 값이 큰 쪽이 첫 번째 메뉴가 됩니다.

주소에 `?a=메뉴&b=메뉴`를 붙이면 메뉴를 바꿀 수 있습니다.

1. 계산 수준 1~3이고 대체값을 쓰지 않은 이름만 받습니다. 받지 못한 이름은 브라우저 콘솔에 경고를 남깁니다.
2. 받은 이름이 하나뿐이면 나머지 하나를 기본 메뉴로 채웁니다. 받은 이름이 시래기국이면 소고기국밥을, 그 밖에는 시래기국을 채웁니다.
3. 받은 이름이 없으면 기본 메뉴 두 개를 씁니다.
4. 받은 이름이 하나라도 있으면 입장 화면에 '오늘의 메뉴' 표시가 나옵니다. `d`에 날짜 문구를 주면 그 뒤에 붙습니다.

```
Δ = round2(round2(E_큰 메뉴) − round2(E_작은 메뉴))      (한 번 바꿀 때 아끼는 양, kg CO₂e)
배수 = E_큰 메뉴 ÷ E_작은 메뉴
```

| 환산 | 계산 | 출처 |
|---|---|---|
| 승용차 km | `round(1000 × Δ ÷ 141.3)` | S013(연료 생산 과정 제외) |
| 스마트폰 충전 횟수 | `Δ ÷ (0.019 kWh × 0.4173 kg/kWh)` | S014, S009 |
| 소나무가 마시는 날수 | `Δ ÷ (6.6 kg ÷ 365일)` | S015 |
| 전기 kWh | `Δ ÷ 0.4173` | S009 |
| 1년 효과 | `Δ × 일주일에 바꾸는 횟수(1~5) × 52` | 같은 환산을 1년 값에 적용 |

화면 문구의 숫자는 이렇게 정합니다.

| 문구 | 계산 |
|---|---|
| '○배 많아요' | 배수가 10 이상이면 정수, 그보다 작으면 소수 한 자리 |
| '이 중 N%는 ○○에서 나와요' | 배출이 가장 큰 재료의 배출 ÷ 큰 메뉴 합계(`mainShare`)를 백분율로 반올림 |
| '약 N%밖에 안 돼요' | `max(1, round(100 ÷ 배수))` |
| '약 N%가 소고기에서 나와요' | 소고기 배출 ÷ 큰 메뉴 합계(`beefShare`)를 백분율로 반올림 |

이야기 장면 가운데 소 사육 다섯 장면(`chFarm`~`chUndo`)은 큰 메뉴의 `beefShare`가 0.5 이상일 때만 나옵니다. 그렇지 않으면 첫 장면('한 그릇을 뜯어봐요')만 나옵니다.

'메뉴 바꾸기 비교' 탭(식단 설계에서는 '메뉴 교환')의 차이도 두 값을 소수 둘째 자리로 반올림한 뒤 뺍니다. 감소율은 `(A − B) ÷ A`입니다.

## 7. 공개 데이터만으로 계산할 때

- 공개한 `data/`에는 1인분 분량(`recipes`, `templates`, `global_qty`), 세그먼트 배율(`segments`), 기존 식단 자료(`corpus`)가 없습니다. 이 앱과 같은 숫자를 다시 내려면 같은 형식의 분량 자료를 직접 만들어야 합니다.
- 분량 자료를 비워 두면 엔진은 이름에서 읽은 재료마다 30 g(20~45 g)을 넣는 수준 3으로 계산합니다. 조리법 대체값과 대체 메뉴 추천도 동작하지 않습니다. 그러면 시뮬레이터의 고기 메뉴 줄이기는 효과가 없습니다. 메뉴 입력칸의 자동완성 목록도 비어 있습니다.
- 비워 두더라도 키는 있어야 합니다. 필요한 것은 아래와 같습니다.
  - `segments`에는 '산업체오피스' 항목이 꼭 있어야 합니다. 없으면 dash.js가 시작하자마자 멈춥니다. `scale`을 1로 두면 기본 분량이 그대로 쓰입니다. `basis`, `src`, `sigma`는 근거 표시와 '어떻게 계산하나요?' 탭에 쓰입니다.
  - dash.js는 시작할 때 `segments["산업체오피스"].scale`, `corpus.results`, `corpus.freq`를 읽습니다(자동완성 목록). 대체 메뉴를 찾을 때도 `corpus.results`와 `corpus.freq`를 읽습니다.
  - 메뉴 비교 화면은 대체값 안내 문구에 `corpus.weighted_median`을 씁니다.
  - 엔진은 경우에 따라 `recipes`, `core_index`, `templates`, `global_qty`, `complete_segments`, `corpus.method_prior`, `corpus.weighted_median`을 읽습니다.
  - `meta`는 읽지 않습니다.
- 공개판 `tokens`에는 제품명 단어 56개가 빠져 있습니다. 제품명이 든 메뉴 이름은 단어 나누기와 레시피 찾기 결과가 달라질 수 있습니다.
- 자기 데이터로 앱을 다시 묶는 명령은 아래와 같습니다. 데이터 JSON에는 위 표의 항목이 모두 있어야 합니다(`meta`는 빼도 됩니다).

```
python3 tools/pack.py src/build/ index.html --payload 내_데이터.json
```

- 공개판 `src/build/`에는 `payload.json`이 없습니다. 그래서 `--payload`를 꼭 붙여야 합니다. 빼면 `src/build/payload.json`을 찾다가 멈춥니다.
- 빌드 전체 절차와 데이터 합치는 예는 [제작 가이드](BUILD_GUIDE.md)에 있습니다.

## 8. 한계

앱 화면과 공개 데이터의 비고에 적힌 한계, 그리고 코드에서 확인한 한계입니다.

| 부분 | 한계 |
|---|---|
| 기준 식단 | 예시 식단이라 실제 식당의 식단표·이용자 수와 다릅니다. |
| 1인분 분량 | 내부 조리지침서 분포의 중앙값에 세그먼트 배율을 곱한 추정입니다. 레시피가 없는 메뉴는 조리법 템플릿이나 재료별 분포, 기본값으로 어림합니다. |
| 해석하지 못한 메뉴 | 기존 식단 데이터의 전체 가중 중앙값이나 조리법별 중앙값으로 대신합니다. 조리법별 중앙값을 쓴 경우에도 화면 안내 문구는 전체 가중 중앙값을 보여 줍니다. |
| 식단이 아닌 문구 | '휴무' 같은 문구를 거르는 규칙은 수준 4에만 적용됩니다. 사전 단어가 든 문구는 수준 3으로 계산됩니다. 예를 들어 공개 데이터만으로 계산하면 '휴무'는 '무'(재료)로 읽혀 무 30 g으로 계산됩니다. |
| 식물성 대체육 | 검증된 배출계수가 없어 계산에서 뺍니다. 계수를 확보하면 다시 계산할 수 있습니다. |
| 배출계수 | 국내 소·돼지·닭고기 외에는 대부분 Poore & Nemecek(2018)의 전세계 평균이나 한국 식품군 평균을 씁니다. 대용(`proxy`) 29종, 미확보(`pending`) 3종이 있습니다. |
| 조리 에너지 | 가정용 조리 원단위입니다. 단체급식 대량조리는 kg당 에너지가 더 낮을 수 있어 상한에 가까운 값입니다. 조리 연료는 도시가스로 가정합니다. 파라미터 비고와 달리 코드는 물·육수 질량도 더합니다(3-2절). |
| 음식물 쓰레기 | 15%는 군 급식의 국방부 추정치를 다른 곳에도 대신 쓴 값입니다. 처리는 퇴비화 기준이며, 사료화·혐기소화는 배출이 더 낮습니다. |
| 운송 | 트럭 운송 계수(`truck_kgco2e_per_tkm`)는 P&N 유통 값에 이미 들어 있어 계산에 쓰지 않습니다. |
| 불확실성 | σ 값은 잠정 가정입니다. 연료 배출계수의 불확실성은 반영하지 않습니다. |
| 시뮬레이터 | 줄인 고기 메뉴는 같은 역할의 대체 메뉴가 채운다고 봅니다. 대체 메뉴가 없으면 바뀌지 않습니다. 양고기나 `육류(불명)`만 읽힌 메뉴도 바뀌지 않습니다. 바뀌는 기간 동안 효과는 직선으로 커지고, 배식량과 배출은 비례한다고 봅니다. 쓰레기 감축은 처리 배출만 줄입니다. 재생에너지 전기는 배출 0으로 봅니다. 조리법 대체값 메뉴는 연료를 전기로 바꿔도 달라지지 않습니다. |
| 환산 | 승용차 141.3 g/km는 연료를 만드는 과정의 배출을 뺀 값입니다. |
